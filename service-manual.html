What we offer

Add a paywall to any app in 2 minutes — without building auth, payments, or license backend.

• JavaScript SDK — two lines of code to add payments

• REST API — verify licenses from any backend

• Cross-device sync — magic link login, restore purchases

What you don't need anymore

  • No backend for payments
  • No Stripe integration code
  • No auth system for license verification
  • No license storage or database
  • No webhooks setup

How it works — simple

  • 1. User opens your app → SDK calls isPaid() → 2MinPay checks license
  • 2. If not paid → showPaywall() → Stripe checkout
  • 3. After payment → SDK gets JWT → isPaid() returns true
  • 4. On new device → user clicks "Restore" → email → magic link → access restored

How it works — detailed

Access logic

  • isPaid() returns true for: Pro (active) OR Trial (not expired)
  • isPaid() returns false for: Free, expired trial, canceled pro
  • Trial: one per user per app, 14 days

Storage (client-side)

// SDK handles all storage automatically (chrome.storage.local or localStorage)

{
  "2minpay_client_id": "tmp_12345",     // temporary ID generated on first init()
  "2minpay_jwt": "eyJhbGciOiJIUzI1..."  // JWT token received after payment or restore
}

Identity flow

  • New user — SDK generates temporary ID, isPaid() → false
  • Pays — Stripe sends email to webhook, we link email + temporary ID
  • Restore on new device — user enters email → magic link → SDK receives JWT → isPaid() → true
  • Same device after reinstall — SDK generates new temporary ID, but server knows email from previous payment → isPaid() → true (auto-recovery)

💡 User email is captured from Stripe checkout. User enters email only once — during restore or first payment.

JavaScript SDK

For web apps, Chrome extensions, React, Vue — anything that runs JS.

Installation

npm install sdk-2minpay

Usage (all you need)

import { init, isPaid, showPaywall } from "sdk-2minpay";

// Initialize (call once)
await init({ appId: "your-app-id" });

// Check if user has access (true = Pro OR active Trial)
if (!await isPaid()) {
  // Shows payment modal with Pro, Trial, and "Restore" button
  await showPaywall();
}

// User has access — load full app
loadApp();

Optional methods (for UI)

// Get full user info (for UI badges, trial countdown, etc.)
const user = await getUser();
console.log(user.plan);        // "free" | "pro" | "trial"
console.log(user.trialEnd);    // timestamp for trial
console.log(user.email);       // if known

// Logout (clear local session)
await logout();

User object

{
  isPaid: true,                 // same as isPaid()
  plan: "trial",                // "free" | "pro" | "trial"
  email: "user@example.com",    // if captured
  trialEnd: 1746547200,         // timestamp for trial
  currentPeriodEnd: null,       // timestamp for pro
}

SDK methods summary

  • init({ appId }) — required first call, generates temporary ID
  • isPaid() → true/false — main method, checks access
  • showPaywall() — shows modal with Pro, Trial, and Restore button
  • getUser() → User — for UI (plan, email, dates)
  • logout() — clears local JWT

REST API (for backend verification)

For Java, Python, Go, Rust, PHP — any language.

Base URL

https://api.2minpay.com/v1

Verify JWT token

POST /verify
Authorization: Bearer <jwt_token>

Response:
{
  "valid": true,
  "plan": "pro",
  "status": "active",
  "expires_at": "2026-05-06T12:00:00Z"
}

JWT tokens are short-lived and automatically refreshed by the SDK. No manual token management needed.

Get user by email (for webhooks)

GET /user?email=user@example.com
Authorization: Bearer <api_key>

Response:
{
  "id": "usr_123",
  "plan": "pro",
  "status": "active",
  "current_period_end": 1746547200
}

Webhooks

We notify your backend when subscription changes.

POST /your-webhook-endpoint
{
  "event": "subscription.updated",
  "email": "user@example.com",
  "plan": "pro",
  "status": "active",
  "currentPeriodEnd": 1746547200
}
  • subscription.created — first payment
  • subscription.updated — renewed, upgraded, canceled
  • subscription.deleted — expired or deleted
  • trial.started — trial activated
  • trial.ended — trial expired

Database Schema (Cloudflare D1 / PostgreSQL)

-- Developer accounts
CREATE TABLE developers (
  id TEXT PRIMARY KEY,
  email TEXT UNIQUE NOT NULL,
  stripe_account_id TEXT,
  api_key TEXT UNIQUE,
  created_at INTEGER
);

-- Applications
CREATE TABLE apps (
  id TEXT PRIMARY KEY,
  developer_id TEXT NOT NULL,
  name TEXT NOT NULL,
  stripe_product_id TEXT,
  public_key TEXT,
  secret_key TEXT,
  FOREIGN KEY (developer_id) REFERENCES developers(id)
);

-- Users (email is key for cross-device sync)
CREATE TABLE users (
  id TEXT PRIMARY KEY,
  app_id TEXT NOT NULL,
  email TEXT NOT NULL,
  temp_id TEXT,                      -- temporary ID from SDK
  created_at INTEGER,
  UNIQUE(app_id, email)
);

-- Licenses
CREATE TABLE licenses (
  id TEXT PRIMARY KEY,
  user_id TEXT NOT NULL,
  app_id TEXT NOT NULL,
  plan TEXT NOT NULL,                -- 'free', 'pro', 'trial'
  status TEXT NOT NULL,              -- 'active', 'expired', 'canceled', 'past_due'
  current_period_end INTEGER,
  trial_end INTEGER,
  paid_at INTEGER,
  trial_started_at INTEGER,
  stripe_subscription_id TEXT,
  cancel_at_period_end BOOLEAN,
  FOREIGN KEY (user_id) REFERENCES users(id),
  FOREIGN KEY (app_id) REFERENCES apps(id)
);

Security

  • isPaid() checks license status on 2MinPay servers — the response cannot be faked
  • If a user removes the if (!isPaid()) check from your code — they can access the feature. This is true for any client-side product.
  • 2MinPay handles payment verification, license storage, and cross-device sync. You don't need a backend.
  • If you already have a backend, we provide JWT tokens for additional server-side verification (optional).
  • JWT tokens are short-lived and automatically refreshed by the SDK. No manual token management needed.

✅ For most extensions and apps, client-side isPaid() is enough. Protected content is only shown when user has paid or active trial.
