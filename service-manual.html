📖 System Specification

This document describes the architecture, data models, and API behavior of 2MinPay.

🏗️ 1. Core Entities

Developer Account

  • Email, Stripe Connect ID, API keys
  • Has many Applications

Application

  • Belongs to a Developer Account
  • Has its own publicKey and secretKey
  • Defines available plans: free, pro, trial
  • Stores Stripe Product/Price IDs

User (End Customer)

  • Identified by userId (provided by developer) or email
  • Belongs to exactly one Application (user is scoped to the app)
  • Has a current plan and status

License / Subscription

  • Stores: plan (free/pro/trial), status (active/expired/canceled), currentPeriodEnd (timestamp)
  • For trial: stores trialStart, trialEnd
  • For pro: stores subscriptionId (Stripe), cancelAtPeriodEnd flag

🎚️ 2. Plan Types & Logic

Free

  • No expiration, always active
  • No payment required
  • Can upgrade to pro or trial

Trial

  • Has trialEnd date (e.g., +14 days from start)
  • After trialEnd → auto downgrade to free OR show paywall
  • Can upgrade to pro anytime (keeps remaining trial days as discount? — optional)
  • One trial per user per application (prevent abuse)

Pro (Paid)

  • Has currentPeriodEnd (billing cycle end)
  • If cancelAtPeriodEnd = true → becomes free after period end
  • If payment fails → status becomes past_due, then canceled after grace period
  • Can be downgraded to free or trial (trial only if never used before)

🔐 Access check logic (server-side):

function hasAccess(userId, appId, requiredPlan) {
  const license = getLicense(userId, appId);
  
  if (requiredPlan === 'free') return true;
  
  if (license.plan === 'pro') {
    return license.status === 'active' && license.currentPeriodEnd > now();
  }
  
  if (license.plan === 'trial') {
    return license.trialEnd > now();
  }
  
  return false;
}

🔌 3. API Endpoints

Client-side SDK (in developer's app)

import { checkAccess, showPaywall, getToken } from "sdk-2minpay";

// Check if user has access
const hasPro = await checkAccess("pro");

// Show Stripe checkout
await showPaywall({ plan: "pro", successUrl: "/welcome" });

// Get JWT token for backend verification
const token = getToken();

Backend API (for developer's server)

  • POST /v1/verify — verify JWT token, returns plan and expiration
  • POST /v1/webhook/stripe — receive payment events (invoice.paid, subscription.updated, etc.)
  • GET /v1/user/:userId — get user's current license status
// Example: backend verification (Java)
POST /v1/verify
Authorization: Bearer <jwt_token>

Response:
{
  "valid": true,
  "plan": "pro",
  "expiresAt": "2026-05-06T12:00:00Z"
}

💾 4. Data Storage (Cloudflare D1 / PostgreSQL)

-- Applications table
CREATE TABLE apps (
  id TEXT PRIMARY KEY,
  developer_id TEXT NOT NULL,
  name TEXT NOT NULL,
  stripe_product_id TEXT,
  public_key TEXT,
  secret_key TEXT
);

-- Users (scoped to app)
CREATE TABLE users (
  id TEXT PRIMARY KEY,
  app_id TEXT NOT NULL,
  user_id TEXT NOT NULL, -- developer's internal user ID
  email TEXT,
  created_at INTEGER
);

-- Licenses
CREATE TABLE licenses (
  id TEXT PRIMARY KEY,
  user_id TEXT NOT NULL,
  app_id TEXT NOT NULL,
  plan TEXT NOT NULL, -- 'free', 'pro', 'trial'
  status TEXT NOT NULL, -- 'active', 'expired', 'canceled', 'past_due'
  current_period_end INTEGER,
  trial_end INTEGER,
  stripe_subscription_id TEXT,
  cancel_at_period_end BOOLEAN
);

💳 5. Payment Flow (Stripe)

  • Developer connects Stripe account via OAuth (Stripe Connect)
  • 2MinPay creates Product & Price in developer's Stripe account
  • When user clicks "Upgrade", 2MinPay creates Stripe Checkout Session
  • After successful payment, Stripe sends checkout.session.completed webhook
  • 2MinPay updates license: plan = 'pro', currentPeriodEnd = now + interval
  • 2MinPay generates JWT token for the user
  • Application receives webhook (optional) or client refreshes token

🔒 6. Security & Best Practices

  • Never trust client-side checks alone. Always verify JWT token on your backend.
  • JWT tokens are signed with 2MinPay's private key — verify with our public key.
  • Tokens expire. Refresh by calling checkAccess() again.
  • Store userId as opaque string — we don't need to know internal IDs.
  • Use webhooks to sync subscription status changes (canceled, expired, renewed).

⚠️ Warning: Client-side check is for UI convenience only. All protected data must be served from your backend after verifying the token.
